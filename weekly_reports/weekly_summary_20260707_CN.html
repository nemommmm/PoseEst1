1. Pipeline × Model 消融实验

1.1 实验设计 & V2 到底改进了什么

Amrit 之前提出了明确要求：想知道最近几周的 pipeline 提升到底是「pipeline 变化带来的」还是「YOLO 模型升级带来的」。为此我把这两个变量拆开跑了一个 2×2 消融矩阵：

YOLOv8m（原始模型）YOLO11l（新模型）
V1 pipeline（几周前的版本）V1+YOLOv8mV1+YOLO11l
V2 pipeline（现在的版本）V2+YOLOv8mV2+YOLO11l

V1 → V2 具体改了哪些东西（回顾上周内容）

为了后续讨论方便，先简要回顾一下 V2 相对 V1 的核心改进：

  • 废弃"二值过滤 + 线性插值 + 滑动平均"的旧链路：V1 里质量过滤器是"通过/不通过"的一刀切，很多质量一般的帧被扔成 NaN，然后 linear_fill 在 NaN 空洞两端画直线，moving_avg 再把它跟真实值来回混合——结果就是在过滤器边界人工制造出本来不存在的大跳变。
  • 换成"质量感知修复 + 关键点级 Savitzky-Golay 平滑"：把每帧关键点分成 valid / repairable / invalid 三档，中等质量帧用邻近 valid 帧插值修复而不是直接丢弃；平滑也从"角度域滑动平均"改成"3D 坐标域 Savgol"，几何上更一致，真实运动峰值不会被压平。
  • 加入 ROI tracking + weighted DLT + soft epipolar constraint：跟踪目标人物 bbox 减少左右视角误配对；三角化时按关键点置信度加权；软极线约束容忍标定误差。
  • 骨长先验（bone constraint）：从稳定帧自动估计人体骨长（不需要用户输入身高），作为软约束加进三角化，帮压制深度方向的抖动。
  • 2D 模型可选升级到 YOLO11l——但本周的实验恰恰要看这一步到底有没有用。

然后把这 4 个 cell 在 5 个不同场景上分别跑一遍：

关于模型升级历史：最初决定把 2D 模型从 YOLOv8m 换成 YOLO11l，是基于 fanbo7 在当时的 v1 pipeline + chain 后处理下测试的结果——那时候 YOLO11l 把 MAE 从 6.75° 降到 2.32°（−65.7%），是非常显著的提升，换模型的决定完全正确。
后来 V2 pipeline 加入了 bone+Savgol+depth 后处理，这套强后处理会自动补偿 YOLOv8m 的检测缺陷，所以近距场景下 YOLOv8m 也能拿到接近的结果。同时 fanbo4 远距 和 fanbo9 双相机等新场景暴露出 YOLO11l 在远距离对手臂关键点的定位偏差更大——所以现在综合起来 YOLOv8m 反而更鲁棒。

1.3 为什么"更大的模型"反而在部分场景变差？

直觉上大模型应该更准，但实测在远距和 fanbo9 上 YOLO11l 明显退步。看一下 raw 2D 检测数据就能看出原因：

← 与相机几何一致性

值得注意的反常现象：在 fanbo4 远距上，YOLO11l 的置信度反而更高（0.982 vs 0.976），但实际的左右一致性和重投影精度都更差。也就是说 YOLO11l 在远距离时是"自信但不准"——这种"过度自信"在下游的双目三角化里危害更大，因为我们的 pipeline 会按置信度加权，把它错误的估计当作可信的输入。

三个具体原因（用大白话说）：

  1. 远距离时人在图像里占的像素少了很多。fanbo7 (180cm) 时人可能占 800+ 像素高，fanbo4 (410cm) 时只有 300-400 像素高。同一个关节的定位空间小了一半以上，任何一点点亚像素级的偏差都被放大。
  2. 大模型不等于每个尺度都好。YOLO11l 参数量比 YOLOv8m 多约 30%，感受野更大、特征更抽象。在训练数据（COCO）里，人物一般是 100-500 像素高的常见大小，所以在 fanbo7 (~500-800 像素高) 这种"正常"场景，它比 YOLOv8m 精细得多。但一旦到 fanbo4 (~300 像素) 甚至更小，训练数据里少见的场景，大模型反而容易靠"人体先验"猜关节位置，产生系统性偏差；而 YOLOv8m 因为容量较小、结构简单，反而更"老实地"跟着像素信号走。
  3. 双目三角化对"左右一致性"极度敏感。就算某个模型的 2D 关节比另一个更准，只要左右两个视角上的偏差不一致（例如 YOLO11l 在左图对手肘偏上 3 像素、右图偏下 2 像素），三角化就会给出一个"歪的" 3D 点。所以对立体系统来说，"左右一致的普通模型"比"单目更准但左右不一致的大模型"更有价值。fanbo4 数据里 YOLO11l 极线残差 p95 从 1.41 涨到 2.16 就是这个问题的直接体现。

这也解释了为什么 fanbo9 的两个相机（更近的 A257 和更远的 A255）都是 YOLOv8m 领先——凡是"远距 + 视角偏"的场景，YOLO11l 的过度自信 + 左右不一致就会成为负资产。

综合结论：V2 pipeline + YOLOv8m 是当前最合适的组合
  • Pipeline 升级（V1→V2）5 个场景全部是正贡献——远距站立场景高达 −52.7% 的 MAE 降低。前几周的进步主要来自 pipeline 改进（三档质量修复、Savgol 平滑、骨长约束、tracking）。
  • Model 升级（YOLOv8m→YOLO11l）在近距站立有效（fanbo7 chain 下 −20.8%），但在远距（fanbo4 +57.8%，fanbo9 +11-13%）和走路场景反而不稳定。
  • V2+YOLOv8m 的优势：没有任何一个场景"翻车"——即使不是最好，也是"够好"，鲁棒性最高。加上 YOLOv8m 模型更小、推理更快，部署也更简单。

2. fanbo9 双相机验证

2.1 为什么做 fanbo9

之前所有测试都只用一个相机（A257 或 A255）。fanbo9 是数据集里第一次两个相机同时录制同一个场景，可以用来验证：同样的 pipeline 配置在两个不同视角/位置的相机上，是否会给出一致的结果？

动作内容：一次做一个单维度动作（头前后 / 头左右 / 头旋转 / 双臂抬起 / 手肘弯曲 / 腰前后弯 / 左右腿抬起 / 左右脚踝旋转...），共约 66 秒。

2.2 两个相机的对比结果

配置A255（更远的相机）A257（更近的相机）差值
V1+YOLOv8m10.75°6.52°+4.24°
V1+YOLO11l12.37°7.13°+5.23°
V2+YOLOv8m ⭐10.70°6.42°+4.28°
V2+YOLO11l12.12°7.15°+4.97°
观察：无论用哪个 pipeline、哪个 YOLO 模型，A257（近）都比 A255（远）好 4-5°。这个差距非常稳定，说明相机到受试者的距离本身就是主导因素——离得越近，三角化的深度精度越高，姿态估计越稳。
结论与之前一致：
  • fanbo4 vs fanbo7 之前就发现远距（410cm）远比近距（180cm）差；fanbo9 用同一次动作的双相机再次印证了这一点，排除了"是不是动作内容不同导致"的干扰。
  • 另外 A257 相机上 V2+YOLOv8m（6.42°）依然是 4 个 cell 里最好的，进一步支持第 1 节的结论。
  • 实际部署时应尽量让受试者进入相机 2-3m 范围内，超过 4m 精度会显著下降。

3. 关于 FastSAM3D 融合方案（原设想不可行）

之前提到过一个思路：既然 FastSAM3D 也能给出人体姿态，能不能把它融合进我们的双目 pipeline，例如把 FastSAM3D 的输出当作"另一路观测"，跟 YOLO 的双目结果一起做三角化 / 加权融合？

本周仔细读了 Fast SAM 3D Body（USC / NVIDIA / Meta，2026）的论文，发现这个方案技术上做不了。核心原因有两个：

3.1 FastSAM3D 直接输出 3D，跳过了 2D→3D 三角化

我们双目系统的工作方式是：

左图 2D 关键点  +  右图 2D 关键点  +  相机标定参数  →  三角化  →  3D 关键点

而 FastSAM3D 的工作方式是：

单张 RGB 图片  →  Backbone + Transformer 解码  →  直接输出 3D mesh + 3D 关节

它的深度是通过神经网络从单目图像"推理"出来的（结合视场角估计和人体比例先验），完全没有走"两幅图片交叉几何"这一步。所以 FastSAM3D 的输出没有可以拿来跟另一个视角做三角化的中间变量——它一步就到了 3D。

3.2 想从 FastSAM3D 里"抠出" 2D 精确坐标也不行

论文里 FastSAM3D 内部虽然用了一个 YOLO11-Pose 检测器，但这个 YOLO 的作用只是给个粗略的 bounding box 让后面的模型知道"人在哪里"（论文原话："these initial keypoints do not require sub-pixel precision; they merely need to establish a reliable bounding region"）。

真正的姿态精度是后面 Transformer 解码时得到的，而这个精度只体现在输出的 3D mesh 上，从来不以 2D 关键点的形式暴露出来。所以就算我们拆开 FastSAM3D 的 pipeline，也拿不到"高精度的 2D 关键点"来跟另一路做立体三角化——能拿到的只有 YOLO11-Pose 给的粗糙 2D，而这个我们自己在 pipeline 里已经在用了，没有增量价值。

结论：FastSAM3D 不适合作为"另一路 2D 观测"融入双目系统。
正确的用法：把 FastSAM3D 当作一个独立的对照参考（就像我们现在的角色定位）——它的输出跟我们的双目输出各自独立，比较 MAE、看哪个更接近 Xsens。要"融合"的话只能在结果层面（例如"当双目 pipeline 置信度低时切换到 FastSAM3D"），而不能在几何层面融合。

4. 下一步计划

Pipeline 层面的探索差不多告一段落，下一步准备做两件事，并行推进：

  • GPU 相关尝试：最近看的一些新方法（比如本周读的 Fast SAM 3D Body）基本都是跑在 GPU 上的，我们目前的 pipeline 主要还在 CPU 上——想去试试一些新东西，同时也顺便熟悉一下 GPU 相关的部署流程。
  • Real-time 部署：跟 GPU 这件事一起做，看看能不能把 pipeline 从目前每秒 2-3 帧提到实时。如果能跑起来就可以尝试做个端到端的 demo。
