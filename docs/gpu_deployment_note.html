YOLOv8m + SKT GPU Deployment Note

RunPod · NVIDIA RTX A6000 48 GB · offline stereo-video file processing · 2026-07-20

1. What was migrated

The existing YOLOv8m + SKT stereo reconstruction pipeline was migrated to a RunPod NVIDIA RTX A6000 instance. The triangulation, angle, and RULA algorithms were not rewritten; the GPU primarily accelerates pose inference for the two camera views.

  • The repository and Python environment are stored on the persistent /workspace volume, with pinned PyTorch, CUDA, Ultralytics, and ONNX Runtime GPU versions.
  • Deterministic CUDA execution disables TF32 and cuDNN autotuning so small numeric changes are not amplified by the crop tracker.
  • Stage timing covers file decoding, pose inference, tracking, stereo geometry, and complete-file processing.
  • The workflow includes a stable SSH alias, remote preflight, resumable transfer, SHA256 verification, and exclusion of sensitive model assets.
The reported “approximately 29 FPS” is offline-file processing throughput for two video files, including file decoding, YOLO, tracking, and per-frame geometry. It is not a completed live system that already includes camera capture, display, and downstream output. The 28.88, 29.23, and 30.21 FPS values are preliminary single-run measurements; deployment claims still require three repeated runs.

The output-equivalence check compares common-frame coverage, angle agreement, validity, and RULA-like agreement with the PyTorch baseline; the TensorRT FP16 export did not pass these checks.

H.264 QP 0 lossless encoding was used for video transfer. H.265 CRF 18 produced smaller files but changed the angle trajectory by approximately 2.28°, so it was rejected for formal results.

3. Unverified items and next GPU work

  1. Repeated timing: use 10 warm-up frames and three independent repeats per configuration; report median and p95 instead of relying on a single mean.
  2. NVIDIA pose models: the TAO Model Zoo provides BodyPoseNet (2D) and BodyPose3DNet (34 3D keypoints). Evaluate keypoint semantics, stereo consistency, angle agreement, and validity before throughput.
  3. Complete video path: test NVDEC/GStreamer/DeepStream and measure capture, decode, inference, geometry, angle, RULA, and output latency together.
  4. Target hardware: RTX 30-series and Jetson devices require direct measurement; A6000 throughput cannot be converted into a reliable “20 FPS on any 30x0 GPU” claim.
DeepStream documents BodyPose3DNet's direct 3D keypoints in a target-local coordinate system and currently uses its 2D output for world-space tracking functions. For this project, the first test should therefore feed its 2D keypoints into the existing fixed calibration and stereo triangulation, rather than treating two local 3D skeletons as a shared world frame.

Official entry points: Ultralytics TensorRT · NVIDIA TAO Model Zoo · NVIDIA DeepStream tracker
