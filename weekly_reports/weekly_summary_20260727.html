Summary of this week
  • The distance-binned box plots do not show a stable rule such as “use YOLO11L nearby and YOLOv8m far away”. I will therefore keep YOLOv8m as the default model.
  • The offline stereo pipeline was moved to an RTX A6000 cloud GPU. The accepted deterministic PyTorch YOLOv8m + SKT pipeline processes stored stereo video at approximately 30–35 FPS.
  • NVIDIA monocular and dense-stereo models produced strong results in individual datasets, but none passed the combined accuracy, RULA, validity and real-time criteria across Fanbo3/4/7. The formal baseline therefore remains YOLOv8m + SKT.

1. Angle disagreement versus distance and YOLO model selection

I compared YOLOv8m and YOLO11L in five distance intervals. For every common valid frame, I calculated the left- and right-hip angular disagreements against the FastSAM3D comparison trajectory and used the median of the two hips. FastSAM3D is treated as an external comparison trajectory, not absolute Ground Truth.

The result is not a smooth distance pattern. YOLOv8m is clearly better around 2.0–2.5 m and slightly better around 3.5–4.0 m, while YOLO11L has lower medians in the other three intervals. In addition, the boxes overlap substantially and the distance intervals contain different sessions, movements and viewpoints. Therefore, the apparent winner is not controlled by distance alone.

This does not directly contradict the earlier distant Fanbo4 result where YOLOv8m was better: that experiment focused on the right elbow and stereo geometric consistency, whereas this figure uses bilateral hip angles against FastSAM3D across mixed sessions. Together they show that model performance also depends on the joint, movement and viewpoint.
Decision: continue using YOLOv8m. YOLO11L can be better in some intervals, but the current data do not provide a reliable distance threshold for switching models. YOLOv8m is also smaller, faster and was more robust in the broader pipeline ablation. A dynamic switch should only be reconsidered after recording the same movement and viewpoint at several controlled distances.

Full evidence: FastSAM3D-referenced hip-distance report.

2. Moving the offline pipeline to a cloud GPU

This week I deployed the offline stereo program on a RunPod NVIDIA RTX A6000 with 48 GB VRAM. One experiment—from reading the videos through triangulation, angles and RULA—runs entirely inside the remote Pod. Only the resulting NPZ files, tables, figures and reports are downloaded to the local computer for inspection.

Recorded left/right video→ Remote CPU reads video→ GPU runs YOLO 2D pose inference→ Remote CPU runs SKT triangulation→ Remote CPU computes angles and RULA→ Results downloaded locally

Necessary code and deployment changes

  • GPU environment: CUDA-enabled PyTorch, Ultralytics and the project dependencies were installed on the Pod. Ultralytics automatically sends the YOLO image computation to the GPU, so the original model did not need to be rewritten.
  • Repeatable output: deterministic CUDA settings were added to reduce small changes caused by automatic GPU algorithm selection. Small 2D changes can be amplified by tracking and stereo triangulation into visible 3D and angle changes.
  • Complete timing: warm-up and repeated tests now measure video reading, left/right YOLO inference, triangulation and the complete pipeline rather than only single-image model speed.
  • Result equivalence: 2D, 3D, angle and RULA outputs are checked before accepting an accelerated backend. TensorRT cannot replace the PyTorch baseline if it changes the formal reconstruction.
  • Remote reproducibility: GPU/software versions, project commit and file hashes are recorded, and SSH/rsync downloads the result package before a Pod expires.

3. NVIDIA official pose-estimation and related stereo models

This section tests NVIDIA official pose-estimation and related stereo models. BodyPose3DNet estimates human pose from a single image. FoundationStereo is not a human-pose model: it first estimates dense stereo depth and then combines that depth with left-view YOLO joints. All three datasets use the FastSAM3D comparison trajectory with fixed offsets. Fanbo3 aggregates eight ergonomic joint angles; Fanbo4 and Fanbo7 evaluate RightElbow.

  • BodyPose3DNet performed well on Fanbo3 and Fanbo7 but failed badly on distant Fanbo4, so its cross-distance robustness is insufficient.
  • FoundationStereo was the strongest distant-view result: Fanbo4 decreased from 10.88° to 2.94°. However, the complete route ran at only 0.73 FPS and its Fanbo3 RULA-like agreement decreased.
  • Fast-FoundationStereo retained most of the Fanbo4/7 improvement but reached only 6.42 FPS, below the 12.5 FPS real-time target.
Final selection: no new candidate passed every frozen cross-dataset gate. YOLOv8m + SKT remains the deployment baseline because it is the only route that is currently robust across all three datasets and real-time on the A6000. FoundationStereo is retained as a promising offline/distant-view research direction.
