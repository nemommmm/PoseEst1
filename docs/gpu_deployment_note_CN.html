5. NVDEC：纯解码有收益，代理输入被拒绝

检查正式结果解释
原 QP0 输入直接走 NVDEC像素验证失败源文件使用了不兼容的 H.264 profile；其表面加速无效，因此不在报告中披露。
兼容 near-lossless 代理，CPU 解码74.659 paired fps 中位数仅为 FFmpeg decode-only。不包含时间戳同步、tensor 预处理、姿态推理、双目几何、角度与 RULA。
兼容 near-lossless 代理，NVDEC112.907 paired fps 中位数（1.512×）；亮度检查通过
代理与正式 QP0 姿态输出3D 差 med/p95 为 1.678/7.825 cm；右肘差 MAE/med/p95 为 2.892/1.955/9.185°等价性失败；仅有 RULA 分箱一致率 1.000 不足以准入。

兼容代理被明确标为 near-lossless，不是 lossless。未来 live implementation 应使用传感器原生的 NVDEC-compatible stream，或直接走 raw/GPU upload，并重新通过完整姿态等价性门槛。

7. 部署决定、局限与证据

  1. 保留已接受基线：确定性 PyTorch FP32 + YOLOv8m + SKT。
  2. 不部署本次 TensorRT engines：仅看模型中位延迟并没有带来可靠的双路文件加速，而且重建输出发生了明显变化。
  3. 把 NVDEC 视为输入链路工程问题：有效的 1.512× 数字只属于 decode-only；测试代理不具备姿态等价性。
  4. BodyPose3DNet Accuracy 只保留为研究线索：必须先改善左右关联和极线一致性，再谈远距、全数据或部署结论。
  5. 不要把 A6000 结果直接换算到 RTX 30 系或 Jetson：目标硬件必须实测。

研究局限

  • 重复部署测速只覆盖两个双目存储序列的 200 帧窗口，不是长时间 live camera system。
  • NVIDIA 可行性结果只覆盖一个 Fanbo7 近距记录和 near-lossless 技术代理，而且双目几何没有通过。
  • Xsens-derived reference 存在校准和 offset 局限，肘部尤其需要谨慎；角度数字表示系统间一致性，而不是真实误差上限。
