YOLOv8m + SKT GPU 部署简要记录

RunPod · NVIDIA RTX A6000 48 GB · 离线双目视频文件处理 · 2026-07-20

1. 做了什么

原有 YOLOv8m + SKT 双目重建流程被迁移到 RunPod 的 NVIDIA RTX A6000。算法的三角化、角度和 RULA 逻辑没有重写；GPU 主要加速左右图像的姿态推理。

  • 仓库和 Python 环境放在持久卷 /workspace，固定 PyTorch、CUDA、Ultralytics 和 ONNX Runtime GPU 版本。
  • 启用确定性 CUDA，关闭 TF32 和 cuDNN autotuning，避免微小数值差异被 crop tracker 放大。
  • 增加文件解码、姿态推理、tracking、双目几何和完整文件处理的分阶段计时。
  • 建立 SSH alias、远程 preflight、断点续传、SHA256 校验及敏感模型排除。
这里的“约 29 FPS”是双路视频文件的离线文件处理吞吐率，包含文件解码、YOLO、tracking 和逐帧几何；它不等同于已经完成现场相机采集、显示和输出的完整 live system。28.88、29.23 和 30.21 FPS 均是初步单次测量，正式部署结论仍需三次重复测试。

3. 尚未验证与下一次 GPU 工作

  1. 重复测速：每个配置 warm-up 10 帧，独立重复 3 次，报告 median 和 p95，而不是只保留单次平均值。
  2. NVIDIA 官方姿态模型：TAO Model Zoo 仍提供 BodyPoseNet（2D）和 BodyPose3DNet（34 个 3D 关键点）。先测试它们的 2D 关键点语义、双目一致性、角度和有效率，再谈 FPS。
  3. 完整视频链路：测试 NVDEC/GStreamer/DeepStream，把采集、解码、推理、几何、角度、RULA 和输出延迟一起计入。
  4. 目标硬件：RTX 30 系和 Jetson 必须实机测量；A6000 的 29 FPS 不能直接换算成“30x0 一定有 20 FPS”。
DeepStream 的 BodyPose3DNet 直接 3D 输出位于目标局部坐标系；官方说明当前世界空间用途主要依赖其 2D 关键点。因此，本项目若测试它，应先把 2D 输出接入现有固定标定和三角化，而不是直接把两个局部 3D 骨架当作同一世界坐标。

官方入口：Ultralytics TensorRT · NVIDIA TAO Model Zoo · NVIDIA DeepStream tracker
